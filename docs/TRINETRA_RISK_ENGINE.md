# TRINETRA Predictive Risk Engine Specification

## 1. Purpose
The TRINETRA Predictive Risk Engine translates forecasted future Network State vectors ($\hat{S}_{t+k} \in \mathbb{R}^{280}$) generated by the Temporal World Model ($\mathcal{W}_\theta$) into mathematically bounded, continuous risk indices and infiltration scores:

$$\hat{S}_{t+k} - S_t \longrightarrow \text{State Deviation} \longrightarrow \mathbf{Risk\ Score} \in [0.0, 1.0] \quad \& \quad \mathbf{Infiltration\ Score} \in [0.0, 1.0]$$

It enables TRINETRA to answer *"How dangerous is the projected trajectory?"* across future horizons $k \in \{1, 3, 5\}$ before anomalous traffic surges cause outages or breaches.

---

## 2. Inputs
- `current_state`: Current 280-dimensional Network State vector $S_t \in \mathbb{R}^{280}$.
- `predicted_state`: World Model predicted future 280-dimensional Network State vector $\hat{S}_{t+k} \in \mathbb{R}^{280}$.
- `horizon`: Integer future prediction step $k \ge 1$ (standard horizons: 1, 3, 5).
- `delta_t`: Elapsed wall-clock time in seconds $\Delta \tau \ge 0.0$.
- `model_confidence`: Optional external model evaluation confidence in $[0.0, 1.0]$ (defaults to `None` if uncomputed).
- Multi-horizon mode accepts `predicted_states: dict[int, np.ndarray]` and `delta_times: dict[int, float]`.

---

## 3. Processing Pipeline
1. **Validation & Non-Leakage Check:** Validates that $S_t$ and $\hat{S}_{t+k}$ are 1-D vectors of length 280 with finite values (zero NaN or Inf).
2. **State Delta & L1/L2 Norms:** Computes signed difference $\Delta S = \hat{S}_{t+k} - S_t$ and magnitude $|\Delta S|$.
3. **Architectural Group Slicing:** Extracts mean absolute deviations across the 5 canonical state groups:
   - Continuous Dynamics (150 features)
   - TCP Flags (48 features)
   - Distribution Shape (66 features)
   - Endpoint & Protocol Diversity (6 features)
   - Macro Indicators (10 features)
4. **Weighted Drift Aggregation:** Combines group deviations using configurable domain weights.
5. **Smooth Saturation Curve:** Maps linear group drift into $[0.0, 1.0]$ using exponential saturation.
6. **Infiltration Indicator Extraction:** Extracts infiltration-sensitive signals (endpoint diversity, macro asymmetry, TCP reset surges) and computes `infiltration_score`.
7. **Trajectory Multi-Horizon Synthesis:** Evaluates monotonicity and escalation across $k \in \{1, 3, 5\}$.

---

## 4. Mathematical Formulation

### A. Group-Weighted Drift
Given group mean absolute deviations $d_g = \frac{1}{|G_g|} \sum_{i \in G_g} |\hat{S}_{t+k, i} - S_{t, i}|$:

$$D_{\text{weighted}} = \sum_{g \in \mathcal{G}} w_g \cdot d_g$$

Default weights:
- $w_{\text{flags}} = 0.30$ (TCP flags indicate attack mechanics)
- $w_{\text{endpoints}} = 0.20$ (port dispersion / protocol shifts)
- $w_{\text{macro}} = 0.20$ (volumetric packet/byte surges)
- $w_{\text{continuous}} = 0.20$ (flow durations, rates, burst times)
- $w_{\text{shape}} = 0.10$ (background distribution variance/skewness)

$$\sum_{g \in \mathcal{G}} w_g = 1.0$$

### B. Normalized Risk Score
$$\text{risk\_score} = 1.0 - \exp\left(-\lambda_{\text{risk}} \cdot D_{\text{weighted}}\right) \in [0.0, 1.0]$$

Where:
- For $D_{\text{weighted}} = 0.0 \implies \text{risk\_score} = 0.0$.
- Monotonically increasing with respect to state drift.
- Strictly bounded in $[0.0, 1.0]$.
- $\lambda_{\text{risk}} = 1.5$ (configurable sensitivity parameter).

### C. Infiltration Score (Heuristic Score, NOT Calibrated Probability)
Infiltration attacks (lateral movement, C2, exfiltration) distort specific endpoint and macro ratios:

$$I_{\text{raw}} = 0.45 \cdot d_{\text{endpoints}} + 0.35 \cdot d_{\text{macro}} + 0.20 \cdot d_{\text{flags}}$$

$$\text{infiltration\_score} = 1.0 - \exp\left(-\lambda_{\text{infil}} \cdot I_{\text{raw}}\right) \in [0.0, 1.0]$$

> [!IMPORTANT]
> **Probability Clarification:**
> The `infiltration_score` is a normalized heuristic indicator of infiltration-related state dynamics. It is **NOT** a calibrated Bayesian posterior probability.

## 5. Outputs
- `HorizonRiskEstimate`:
  - `horizon`: int ($k$)
  - `delta_t`: float ($\Delta \tau$)
  - `risk_score`: float in $[0.0, 1.0]$
  - `infiltration_score`: float in $[0.0, 1.0]$
  - `confidence`: float in $[0.0, 1.0]$ or `None`
  - `state_change`: `StateChangeSummary` (L1 drift, L2 drift, per-group drifts, max drifting feature name & value)
- `RiskTrajectory`:
  - `aggregate_risk`: float in $[0.0, 1.0]$
  - `aggregate_infiltration`: float in $[0.0, 1.0]$
  - `horizon_estimates`: dict mapping horizon $k \to \text{HorizonRiskEstimate}$
  - `peak_horizon`: int
  - `is_escalating`: bool

## 7. Configuration
Configurable via `PredictiveRiskEstimator` constructor arguments:
- `group_weights`: Optional custom dictionary mapping group names to weights.
- `risk_sensitivity`: Scaling coefficient $\lambda_{\text{risk}}$ (default `1.5`).
- `infiltration_sensitivity`: Scaling coefficient $\lambda_{\text{infil}}$ (default `2.0`).

---

## 8. Tests
Covered by 12 comprehensive unit tests in `tests/test_risk_estimator.py`:
- `test_valid_state_input`: Standard validation and dataclass output verification.
- `test_zero_state_change`: Verifies `risk_score == 0.0` and `is_zero_drift is True`.
- `test_small_vs_large_state_change`: Verifies monotonic scaling ($0 < \text{small} < \text{large} \le 1.0$).
- `test_bounded_output`: Tests extreme inputs ($+10^6$) strictly saturate at $\le 1.0$.
- `test_deterministic_output`: Verifies identical floating-point results across repeated runs.
- `test_invalid_shape_rejection`: Rejects wrong 1D lengths and 2D arrays with ValueError.
- `test_nan_and_inf_rejection`: Rejects NaN and Inf vectors.
- `test_empty_input_rejection`: Rejects `None` inputs.
- `test_confidence_handling`: Preserves valid confidence, rejects out-of-bound values ($>1.0$).
- `test_trajectory_generation`: Verifies multi-horizon $k=1, 3, 5$ aggregation and escalation flag.
- `test_trajectory_empty_rejection`: Rejects empty trajectory dictionaries.
- `test_invalid_horizon_and_delta_t`: Rejects $k < 1$ and $\Delta \tau < 0$.

---

## 9. Limitations
1. **Uncalibrated Output:** `infiltration_score` reflects feature drift and is not calibrated against real ground-truth base rates.
2. **Deterministic Heuristic:** Group weights are established based on network security domain principles rather than end-to-end gradient learning.
3. **No External Context:** Does not evaluate external threat intelligence feeds (which are handled downstream by `ThreatIntelAgent`).
