# CyberHeal AI: World Model Specification ($\mathcal{W}_\theta$)

## 1. Why a World Model is Needed

In traditional reactive Security Operations Centers (SOCs), detection occurs **after** malicious payloads land, anomalies spike, or systems crash. CyberHeal introduces proactive predictive intelligence via a **World Model**:

$$\text{Current Network State } S_t \in \mathbb{R}^{280} + \text{Horizon } k + \text{Elapsed Time } \Delta \tau \longrightarrow \mathbf{Predicted\ Future\ State\ \hat{S}_{t+k} \in \mathbb{R}^{280}}$$

The World Model models the continuous transition dynamics of enterprise network telemetry. By predicting how the network state will evolve $k$ windows ahead, CyberHeal can evaluate whether the projected trajectory deviates toward high-risk attack dynamics (e.g. escalating port scans, SYN flood saturation, slow data exfiltration) **before** disaster strikes.

---

## 2. Formal Mathematical Formulation

$$\hat{S}_{t+k} = \mathcal{W}_\theta\left(S_t, k, \Delta \tau\right) = S_t + \Delta \hat{S}\left(S_t, k, \Delta \tau; \theta\right)$$

Where:
- $S_t = f(X_{t-T+1:t}) \in \mathbb{R}^{280}$: Current deterministic Network State at observation window $t$.
- $k \in \{1, 3, 5, \dots\}$: Discrete future observation window step.
- $\Delta \tau = \tau_{t+k} - \tau_t \ge 0$: Actual continuous elapsed wall-clock seconds.
- $\hat{S}_{t+k} \in \mathbb{R}^{280}$: Model-predicted future Network State.
- $S_{t+k} = f(X_{t+k-T+1:t+k}) \in \mathbb{R}^{280}$: Actual ground-truth future Network State.

### Critical Distinction:
- **Prediction**: $\hat{S}_{t+k}$ (generated by $\mathcal{W}_\theta$ using only past observations up to $\tau_t$).
- **Actual**: $S_{t+k}$ (observed only when wall-clock time reaches $\tau_{t+k}$).
- **Future Step (Step 7)**: Prediction error / trajectory deviation $||\hat{S}_{t+k} - S_t||$ or divergence from normal baseline drives the proactive **Risk Score**.

---

## 3. Residual Dynamics Architecture

Rather than predicting the entire raw future state from scratch, $\mathcal{W}_\theta$ learns the **residual trajectory delta** $\Delta \hat{S}$:

```
Current State S_t in R^280 ────┐
                               │
Conditioning (k, Delta tau)    │
  ├─ Horizon Embed (R^16)      │
  └─ Time MLP log1p(dt) (R^16) │
        │                      │
        ▼                      │
  Conditioning c in R^32       │
        │                      │
        ▼                      │
Concatenate [S_t, c] in R^312  │
        │                      │
        ▼                      │
Linear Projection + LayerNorm  │
        │                      │
        ▼                      │
2x Pre-LayerNorm Residual      │
   Dynamics Blocks (GELU)      │
        │                      │
        ▼                      │
LayerNorm + Delta Linear Head  │
        │                      │
        ▼                      │
Predicted Delta S_hat in R^280 │
        │                      │
        ▼                      │
  (+) <────────────────────────┘
   │
   ▼
Predicted Future State S_hat_{t+k} in R^280
```

### Advantages of Residual Dynamics:
1. **Natural Persistence Fallback**: If the network is quiescent and no dynamic shift occurs, $\Delta \hat{S} \approx 0 \implies \hat{S}_{t+k} \approx S_t$. The model automatically matches the persistence baseline for steady-state flows.
2. **Gradient Stability**: Residual connections prevent vanishing gradients across deep state-to-state transformations.
3. **Compact Footprint**: 143,816 parameters (~580 KB checkpoint), enabling high-throughput CPU inference (< 1 ms per window).

---

## 4. Time & Horizon Conditioning

Network events operate across variable timescales. $\mathcal{W}_\theta$ conditions on both discrete window count and continuous elapsed seconds:
- **Horizon Embedding**: $k \in \{1, 3, 5, \dots\}$ is embedded into $\mathbb{R}^{16}$ via `nn.Embedding(16, 16)`.
- **Elapsed Time Projection**: Continuous $\Delta \tau$ is transformed via $\log(1 + \Delta \tau)$ and projected through a 2-layer MLP `Linear(1, 16) -> GELU -> Linear(16, 16)`.
- Combined conditioning vector: $c \in \mathbb{R}^{32}$.

---

## 5. Loss Function: Huber Regression

The model optimizes the robust Huber Loss (Smooth L1 with $\delta = 1.0$):

$$L_\delta\left(\hat{S}, S\right) = \begin{cases} \frac{1}{2}\left(\hat{S} - S\right)^2 & \text{for } |\hat{S} - S| \le \delta \\ \delta \left(|\hat{S} - S| - \frac{1}{2}\delta\right) & \text{otherwise} \end{cases}$$

Huber loss combines quadratic penalization for subtle telemetry drifts with linear penalization for sharp burst outliers, preventing massive packet surges from destabilizing gradient updates.

---

## 6. Baselines for Rigorous Comparison

Before claiming any learned utility, the World Model is evaluated against:
1. **Persistence Baseline**:
   $$\hat{S}_{t+k}^{\text{pers}} = S_t$$
   Assumes static zero-drift state.
2. **Linear Dynamics Baseline**:
   $$\Delta \hat{S}^{\text{lin}} = \mathbf{W} [S_t, k, \log(1 + \Delta \tau)] + \mathbf{b}$$
   Closed-form L2 Ridge regression.

---

## 7. Overlapping-Window Leakage Prevention

To guarantee that overlapping sliding windows ($T=20, s=10$) never leak raw packets across partitions:
- **Rule**: Raw chronological splitting is executed **first** on the raw flow sequence.
- **Enforcement**: Windows and Network States are generated strictly **inside** each partition.
- **Empirical Proof**: `tests/test_world_model.py::test_overlapping_window_raw_observation_isolation` validates:
  $$\text{Flows}(\text{Train}) \cap \text{Flows}(\text{Test}) = \emptyset$$
